## Current state

- **Branch:** `dev`, clean (the three.js + GSAP presentation deck is committed; see Recent changes). `feat/postgres` (Prisma + PostgreSQL server) was tested by the user and merged into `dev` on 2026-10-15, then deleted. `main` is behind `dev` (the user merges into `main` themselves).
- **App:** Expo SDK 57 dev build on the user's Android phone (`ai.deemo.app`), Metro on the PC. The native build includes Firebase, Google sign-in, the document picker, the VoiceCommunication mic patch, `react-native-svg`, print and sharing, and the owl app icon and splash.
- **Server:** `server/`, `bun run dev` on :3000. The phone reaches it through the user's Cloudflare tunnel (`https://api.deemo-ai.com/api` → localhost:3000), set in `client/mobile/Deemo/.env.local` (`EXPO_PUBLIC_API_URL`, gitignored). Without that file the app falls back to `http://localhost:3000` over `adb reverse tcp:3000 tcp:3000`. The server strips the tunnel's `/api` prefix.
- **Data:** Firebase Authentication for sign-in only (email/password with email verification, Google); all app data in PostgreSQL through Prisma 7 (`server/prisma/schema.prisma`, 17 tables: users, projects, analyses, rubrics, rubric_criteria, sessions, session_turns, session_flags, reports, report_criteria, report_contradictions, report_turns, report_fixes, groups, group_members, live_starts, rate_limit_counters). Only the server reads and writes it (`DATABASE_URL` in `server/.env`).
- **AI:** Gemini Live (`gemini-3.8-live`) for the panel. Analysis, rubric reading and scoring use a Gemini-only fallback chain (`FLASH_MODELS` in `server/src/shared/ai/gemini.ts`): 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite → 3.1 Flash-Lite. The OpenAI backup is gone (consent `2026-10.3`).
- **Recently landed (2026-10-14):** Deemo is an owl; email verification; names for email accounts; DiceBear avatars with a picker (saved per account) and a shining gold ring for Premium; compact Group readiness (Home) and capstone group (summary screen) cards; GitHub issues #2, #3, #7, #8, #9 fixed (#4, #5 kept as is by the user's decision).
- **Codex tooling:** agent-device MCP is registered in the user's Codex config. `AGENTS.md` (a copy of CLAUDE.md for Codex) and `.codex/config.toml` are committed; keep AGENTS.md in step when CLAUDE.md changes.

## Gotchas

- **Screen data is cached for 60 s:** focus refreshes skip the server if the list loaded under a minute ago (`freshFor` in `src/utils/fresh.ts`). After a server-side change the app makes itself, call `refresh(true)` or `invalidate` the store's freshness, or the change shows up only after a minute or a pull to refresh.

- **Presentation deck:** the phone's screens bake fonts into canvas textures, so `screens.js` waits on `document.fonts.load` first; fonts come from Google Fonts, so offline the screens and slides fall back to system fonts (libraries are vendored, fonts are not). The WebGL loop and GSAP both run on rAF: in a hidden browser tab or the hidden Claude preview pane nothing animates and freshly loaded slides look blank until a frame runs (screenshots force one). To update three.js, rebuild `vendor/three.js` from an entry that does `export * from 'three'` plus the `RoomEnvironment` addon. Slot sizes in `styles.css` decide the phone's size and position; poses live in `POSES` in `js/phone.js`. Deemo's lines and moods are the `data-say`/`data-deemo` attributes on each slide; if the app's Deemo drawing changes, port it to `js/deemo.js` too.
- **Redrawing the diagrams:** run the scripts in `docs/diagrams/src` with Node (`bun install` there first); ELK's bundled worker fails under Bun. `shot.sh` renders the HTML to a 2x PNG with headless Chrome, which only writes the file when its output goes to a pipe. Flowcharts use a hand grid on purpose: ELK reverses loops and breaks the spine.
- **Avatars:** the face is a DiceBear seed in `users/{uid}.avatar` (absent = the uid-hash default, computed by the server only). The picker shows fixed pages of faces (`pageOfFaces` in `utils/avatar.ts`: FNV-1a of `deal-<page>-<i>`, the same for everyone), so reopening it or going back to a seen page is served from the image cache; only a never-seen page downloads its 8 PNGs (under DiceBear's 10 PNG/s limit; a 429 just shows initials for that tile). Each opening starts at page 0.
- **DiceBear:** the public API is free for non-commercial use (fine for the capstone; self-host or switch to `@dicebear/core` 10.x + `@dicebear/styles` with `SvgXml` for a commercial release). It rejects a color list whose comma is URL-encoded (`%2C`), and its CDN caches by the normalized URL, so one bad request can make the good form fail too; `avatarUrl` builds the query by hand. Each avatar load tells DiceBear the device IP and the hashed seed.
- **Display names:** the server owns the name: `PATCH /me { name }` writes the `users` row, then the Firebase `displayName` (and reverts the row if Firebase refuses). The Firebase-to-row sync only fills an empty name, so a token minted before a rename can't undo it. During sign-up (email not yet verified, the server refuses) the app sets the Firebase name directly and the server copies it on the first verified request.
- **Email verification:** the server rejects unverified email accounts (403), so `use-session.ts` only loads `/me` once `user.emailVerified` is true, and the root layout only refreshes projects for `signedIn && verified`. Firebase reports verification only after `reload(user)`, and the ID token keeps `email_verified: false` until a forced refresh (`checkVerified` does both). Accounts made before this change must verify once.
- **Build and update environments are separate:** preview OTA publishes must use `--environment preview`. A correct EAS Build log and `--clear-cache` do not repair an already downloaded OTA bundle. The installed release can run the newest compatible downloaded update even offline; clearing Android app data deletes that update cache as well as the sign-in state. Repair by publishing a correct compatible update and cold-launching online; preserve app data. Keep the API URL plain text or sensitive in EAS so Update can read it. Release exports now require HTTPS; local development still permits the USB localhost fallback.
- **`EXPO_PUBLIC_*` and the Metro cache:** values are inlined into JS, and `metro.config.js` includes them in the transform cache key. The earlier cache explanation did not resolve this incident: inspection confirmed that the served preview OTA asset itself had localhost. Check the installed update and its publishing environment before rebuilding again; EAS Build's `--clear-cache` does not clear the phone's downloaded updates.
- **Started offline:** an expired Firebase ID token can't refresh without a network, and the first refresh after reconnecting may still fail; `api()` forces one refresh before giving up.
- **Session admission:** quota counts issued starts, including abandoned/early-ended rounds. The `users` row keeps `sessionDay/sessionCount` and `live_starts` keeps each start (setup fingerprint, pending lease and cached ephemeral token); on `dev` these are Firestore documents. Pending mints lease for 30 seconds; provider fetch times out after 20 seconds and failures refund only their own reservation. Token expiry stays fixed at admission (chosen length + 30 minutes); a very long pause requires a new round. Resumption reuses the same `uses: 1` token, per Google's [ephemeral-token guide](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens). These records are server-only and deleted by existing account deletion; they hold no audio/raw files. The cap applies to Live starts, not manuscript/rubric reading or report rescoring.
- **Testing session admission:** `DEEMO_LIVE_INTEGRATION=1 bun test tests/live.integration.test.ts` in `server/` uses real Firebase Auth and the Postgres at `DATABASE_URL` (use a test database) with one disposable `*@deemo.test` account, fakes Gemini, and cleans up (deleting the user row cascades). It spends no AI credit. On this Windows sandbox, Bun tests/Doctor need execution outside the sandbox (otherwise module/alias resolution fails with `EBADFD`).
- **Prisma 7 is pinned (`7.10.0`):** `bunx prisma` without a version would pull Prisma 8 (a release candidate with a different toolchain: no `schema.prisma`, no isolation levels). The client is generated into `server/generated/prisma` (gitignored; `postinstall` runs `prisma generate`), needs the `@prisma/adapter-pg` driver adapter, and the CLI reads `DATABASE_URL` through `server/prisma.config.ts` (run it under Bun, `bunx --bun`, so `.env` loads). Prisma Postgres apps should use the pooled host; serializable transactions work through it.
- **Rate limits:** counted in `rate_limit_counters` (fixed windows, shared by every server instance); limits in `LIMITS` (`server/src/shared/rate-limit.ts`). Behind the Cloudflare tunnel the client IP comes from `cf-connecting-ip`. If the database is unreachable the limiter lets requests through (logs "rate limit unavailable").
- **Express 5:** thrown errors and rejected promises in routes and middleware reach `errorHandler` (`shared/errors.ts`), so handlers throw `AppError` instead of writing error responses.
- **Gemini model aliases:** `gemini-3.7-flash` and `gemini-3.5-flash` still answer but just route to 3.8 and 3.6 Flash, so listing them as fallbacks adds nothing. `gemini-3.1-flash-lite` shuts down 2027-05-07 (replacement 3.5 Flash-Lite). Flash-Lite defaults to `minimal` thinking; `forModel` gives it `medium` unless the request sets a level (the rubric asks for `low`). 3.8 Flash rejects `minimal`.
- **Gemini overload:** under high demand the newest Flash models hang or answer 503 while older ones still work. The cooldown handles it; the first request after an outage starts can still take up to a minute. `thinkingLevel: "minimal"` is rejected by these models; use "low".
- **Gemini free tier:** the key is on the free tier: 20 Flash requests/day per model, and inputs may be human-reviewed. The fallback chain stretches the cap but doesn't fix privacy. **Paid tier is the open blocker** (user action).
- **GPG signing:** commits are signed and the passphrase prompt opens on the user's desktop. When it times out, leave the changes staged on the feature branch and give the user the commit command. Never use `--no-gpg-sign`.
- **Changing `.env.local`** needs a Metro restart with a clear cache (`bun start -c`); `EXPO_PUBLIC_*` values are baked in when the bundle is built.
- **adb over Wi-Fi:** when the phone reconnects (new port), `adb reverse` is lost and the app silently can't reach the server ("Getting the panel ready…"). Rerun `adb reverse tcp:3000 tcp:3000`.
- **Line endings:** many files are CRLF on disk. Scripted string replacements must normalize `\r\n` first, or use the Edit tool.
- **Testing on the device:** use throwaway Firebase accounts (`*@deemo.test`) and delete them afterwards (Delete my data in the app, or delete the `users` row, which cascades, then `deleteUser`). Don't change the user's own account settings; one stray tap once switched off "Allow typed answers".
- **Group integration test** (`server/tests/groups.integration.test.ts`) talks to the real Firebase project and the Postgres at `DATABASE_URL`; it only runs with `DEEMO_GROUP_INTEGRATION=1` and cleans up its own `*@deemo.test` accounts.
- **Previewing the PDF without the phone:** render `reportHtml()` to an HTML file and print it with headless Chrome (`chrome --headless=new --no-pdf-header-footer --print-to-pdf=out.pdf file:///…`). Android's WebView prints the same way.
- **Charts:** follow the dataviz rules: solid hairline grid (never dashed), 2 px line, text in text tokens (never the series color), one series needs no legend, readout over a floating tooltip on touch screens.
- **Animation budget:** animate transform/opacity only (never height/width/margins per frame); endless loops cancel on unmount; periodic flourishes (blink, badge glint) use timers, not running frame loops; anything that counts or ticks re-renders only its own small component.
- **Press feedback:** pressable surfaces use `PressableScale` (not `Pressable` with an opacity style); the four bottom tabs stay plain (tapped too often to animate). Never pass a `transform` in `PressableScale`'s style (its press scale replaces it); put `entering` animations on its wrapper (it does this itself).
- **Waits:** new work the server is doing (reading a manuscript, scoring) uses `Working` (steps and a progress bar); opening something that already exists uses `Fetching`; a list loading for the first time uses `Skeleton` with bones shaped like its rows.
- **Rubrics:** a project has either `weights` (the default five criteria) or `rubric` (the panel's own, which wins). Report criteria come from whichever the session snapshotted, so old reports keep their criteria.
- **Deemo is drawn in the owl's units** (viewBox around x 64–336, y 62–354; see `docs/design/owl/make-owl.ts`). Change the study first, then port. The waving wing lives on its own absolutely positioned layer so it can rotate natively; RN-SVG `G` rotation can't be animated through Reanimated animated props.
- **Deemo:** never on the live session, paused overlay or question card (design D4); its lines are scripted, at most two sentences, no exclamation marks (D3). Worklets (`useAnimatedStyle`, `useAnimatedProps`) can't call plain JS helpers; compute numbers outside them or use module constants.
- **`expo install` in a cloud session** fails (the proxy blocks Expo's version API). Take the SDK's pinned version from `node_modules/expo/bundledNativeModules.json` and `bun add <pkg>@<that version>`.
- **Rules:** never commit on `main`; never run native rebuilds (tell the user); risky work goes on its own branch and is merged into `dev` after testing (CLAUDE.md).
