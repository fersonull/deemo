- **App:** Expo SDK 57 dev build on the user's Android phone (`ai.deemo.app`). The native build includes Firebase, Google sign-in, the document picker, the VoiceCommunication mic patch, `react-native-svg`, print and sharing, and the owl app icon and splash. Everything since then is JS only (no rebuild needed).
- **Server:** hosted on Render's free tier (it sleeps after 15 min idle; the first request after that takes ~1 min). Locally, the app reaches a dev server through the URL set in `client/mobile/Deemo/.env.local` (`EXPO_PUBLIC_API_URL`, gitignored); without that file the app falls back to `http://localhost:3000` over `adb reverse tcp:3000 tcp:3000`. The server strips the tunnel's `/api` prefix. `FIREBASE_SERVICE_ACCOUNT` takes a file path (local) or the key's JSON (hosts).
- **Data:** Firebase Authentication for sign-in only (email/password with verification, Google); all app data in PostgreSQL (Prisma Postgres) through Prisma 7. The merged schema has 22 tables, including admin actions, notices, read receipts, filtered recipients and device push tokens; sessions now also have `agenda`, and turns have `topic`. `add_user_course` and `add_analysis_field` were applied to the user's database; migration state must be confirmed against the target database; conflict resolution did not apply migrations.
- **AI:** Gemini Live (`gemini-3.8-live`) for the panel, one session and voice per panelist (Kore, Charon, Orus). Analysis, rubric reading and scoring use the Gemini-only fallback chain (`FLASH_MODELS` in `server/src/shared/ai/gemini.ts`): 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite → 3.1 Flash-Lite. The key is still on the **free tier** (blocker, see Next task).

Sessions cover a manuscript/stage agenda rather than a chosen length; safety caps are 30 minutes Free / 60 minutes Premium (`server/src/modules/identity/domain/plan.ts`).
- **Scope (decided 2026-10-17):** DEEMO accepts any course's manuscript; the study (and the paper's claims) stays 4th-year BSIT at PMFTCI. The manuscript's detected field decides the panel (field expert, best-fit seating for 1–2 panelists); the onboarding course is the fallback. Prompts are program-neutral.

## Gotchas

- **Never open a system picker (files, photos, camera) from inside a `Sheet`/`Modal` on Android.** Hide the sheet first, as `upload-sheet.tsx` does, or the Modal ends up dismissed natively while React thinks it is open.
- **Upload caps: PDF 50 MB is Gemini's limit, not ours.** PDFs go through the Files API (uploaded once, deleted after reading), which has the same 50 MB PDF cap. A 100 MB DOCX is held in memory 2–3× while it uploads; watch the Render instance's memory. A Visio diagram pasted as EMF/WMF is skipped (not an image type Gemini reads).
- **Downgrading to Free keeps every manuscript.** The one-manuscript limit only blocks new uploads and joins (until the student holds none); existing ones stay practicable. Free's other limits (1 panelist, no Final, 30 min, 5 a day) apply at once.
- **Flat content surfaces spread `lit` (theme.ts).** A new sand card, group or speech bubble should start with `...lit` so it catches the same light. Don't put it on inputs, chips or tracks, and never add an outer shadow to content.
- **Sessions are backed up until the server has them.** `sessionBackup` (document directory, uid-scoped) is written mid-session and by `sessions.submit`, and cleared only on a confirmed save. Anything that submits a session must go through `sessions.submit`, or a stale backup will be offered again on Home.
- **`ink` is text, `fill` is a surface.** Solid dark surfaces (main buttons, selected chips, the tab bar, the Premium card) use `colors.fill` with `onFill` text, never `colors.ink` + `colors.paper`, or the dark theme turns them into white slabs.
- **Themes are applied before any module builds styles.** `index.ts` imports `utils/theme-choice.ts` first, which fills `colors` with the saved palette. Never read colours into module scope before that (no theme work in `colors.ts` beyond the palettes). Character art and the PDF import `light` on purpose. A new colour token needs a value in both `light` and `dark`.
- **Spacing comes from `space` in `theme.ts`.** Use its steps and roles (24 between sections, 8 from a label to its content and between stacked cards, 16 card padding, 24 before a main action, a 20 gutter). Avoid off-scale values and negative margins.
- **One light language, no raised layers.** Content surfaces spread `lit` from `theme.ts`; pressable main actions and chips pass `lit` to `PressableScale` (the light goes out while held). Don't reintroduce lower layers or outer shadows.
- **Scroll screens handle the keyboard in `Screen`.** Don't wrap a `Screen scroll` in another `KeyboardAvoidingView`: the padding doubles. Long lists go through `Screen`'s `list` prop (a `FlatList` with the screen's content as its header), not `.map` inside the scroll view.
- **Device files:** `onboarded` (welcome slides seen) and `practice-setup.json` (last setup) live in the app's document directory through `expo-file-system`. `practiceSetup.reset()` deletes the setup file on sign-out. Anything added to the setup store is persisted automatically, so keep per-run values (like `weakFrom`) out of the restored state.
- **Onboarding is per phone, consent is per account.** `utils/onboarded.ts` (a file flag) only decides whether the welcome slides show. Consent is decided by the account's `consentAt` (root layout `needsConsent`). Don't gate consent on the flag, and keep `session.signOut()` clearing the device consent.

- **Continuous ERD:** the user requires direct, continuous table-to-table lines, with no reference chips or separate domain sheets. The fixed orthogonal routes in `docs/diagrams/organized-erd/src/generate.mjs` are tested for coverage, connectivity, endpoint attachment, crossings, shared segments and table intrusion. Re-route when table heights or relationships change. Run generators with Node (ELK 0.9.3's bundled worker fails under Bun here); PNG export uses existing Playwright through `NODE_PATH` and installed Chrome. Use SVG when zooming; final paper/print sizing is unverified.

- **The agenda is the single source.** `buildAgenda` (`server/src/modules/practice/domain/agenda.ts`) feeds three places: the prompt (each seat's items), the per-seat `ask_question.topicId` enum, and scoring (rebuilt at submit and stored on `sessions.agenda`). Change topics there only. The app takes the agenda from the token response and doesn't mirror it. `CAP_MINUTES` in the app's `constants.ts` mirrors `capMinutes` in `identity/domain/plan.ts`. With an older server (no `agenda` in the token) the engine falls back to no agenda rules.

- **No expo-notifications next to RN Firebase messaging.** Both register a FirebaseMessagingService and only one receives messages. The notification icon, colour and channel name come from `plugins/with-notice-notifications.js` plus `firebase.json` instead.
- **Push goes to tokens, not users.** `push_tokens` is keyed by FCM token (one row per phone); sign-in upserts it to the current account and sign-out deletes it. Never put the full notice body in a push: `pushBody` trims it to about 160 characters.
- **Filtered notices are a snapshot.** A notice with `segment` set is visible only through its `notice_recipients` rows (written once, at send time). Don't evaluate the filters at read time. The admin's filter values (`lib/notice-audience.ts`) must match `Segment` in `server/src/modules/notices/domain/notice.ts`.
- **Gestures need the root wrapper.** `app/_layout.tsx` renders a `GestureHandlerRootView` (added for the floating notice); keep it as the outermost view or every `GestureDetector` stops responding.

- **Moving the database:** `OLD_DATABASE_URL=… NEW_DATABASE_URL=… bun scripts/copy-db.ts [--yes]` from `server/`, with the direct `db.prisma.io:5432` URLs (not `pooled.`). Run `db:deploy` against the new one first. Don't sign in to the app against the new database before copying: those rows are wiped by `--yes`.
- **`client/promo` runs at 60 fps, in overlapping scenes.** `src/Promo.tsx` places each `src/scenes/*` at `S.*` (`script.ts`), overlapping by `OVERLAP` frames. The phone is a separate layer whose path is `pose(g)` in `Promo.tsx`, by global frame. Retime by changing a line or `MIN` in `script.ts`. Cue frames inside a scene (`HOOK_Q`, `UPLOAD_READ`, `LIVE`) are shared with the SFX in `Promo.tsx`; step text leaves `len - 66` so the crossing phone never passes over words. For quick checks: `bunx remotion bundle --out-dir <dir>` once, then `bunx remotion still <dir> Promo x.png --frame=N --scale=0.5` (about 4 s each).
- **`client/promo` copies art and facts.** `ui.tsx` `C` mirrors the app's `colors.ts`. `components/deemo.tsx` and `panel-face.tsx` port the app's owl and busts (the path data is copied; `parts.ts` can't be imported because `personas.ts` needs the `@/theme` alias). The Upload screen restates `SAMPLE_ANALYSIS` (ReqTrack) and the report its fixes. Update them if those change. Edit the lines in `src/script.ts`, then delete that line's `public/audio/vo-<id>.mp3` and run `bun run audio`; scene lengths follow automatically. The ElevenLabs Music API is paid-only, so on a free plan the script falls back to a 30 s looping sound-effects bed.

- **Presentation screen previews:** canvas approximations, not live app screenshots. New Consent and Profile data-control screens mirror current app copy. If a preview shows the old splash or reports `DRAW[id] is not a function`, hard-refresh the deck to replace cached ES modules.
- **`client/web/site` motion rules:** nothing animates in on its own (no fade/rise reveals, by the user's call); motion is the scroll-following phone and responses to input (course chips, Deemo's mood hop, FAQ). Lenis owns scrolling, so don't add `scroll-behavior: smooth` back. The phone is a third copy of the deck's model/screens (`src/three/model.ts`, `screens.ts`); keep it in step with `client/web/presentation/js/`. Previewing it in the desktop app's browser pane needs the pane visible (a hidden pane pauses requestAnimationFrame, so the phone never draws).

- **`client/web/site` mirrors real logic, not just real copy.** `src/panel-data.ts` is a hand-copy of `server/src/modules/practice/domain/panel.ts`'s `COURSE_FOCUS`/`FIELD_EXPERT`/`PRIORITY`/`lineup` and `identity/domain/course.ts`'s `COURSES`/`COMPUTING` — if the real panel's course list, focus text or seating priority changes, this file goes stale silently (no shared import; it's a separate Vite project with no server dependency on purpose). Same for `tokens.css`/`deemo.ts` vs. the app's `colors.ts`/`theme.ts`/`components/deemo` — three copies to keep in step now (app, `presentation`, `site`).

- **Profile course = the manuscript's field, else the account course** (`profileCourse` in the app, the same rule in `live-token.ts` and scoring). The analysis detects `field` and `itField`; the upload sends `domain: "General"` and `finishAnalysis` overwrites it. Editing the field to a non-computing one resets the project's domain to "General" (`editAnalysis`).
- **Seat vs persona:** a seat is the speaking order (engine, reducer, `question.panelist` and live `Line.who` during a session); a persona is who sits there (face, name, voice). `lineup(course, panelists)` maps seat → persona and must stay identical in `server/src/modules/practice/domain/panel.ts` and `client/mobile/Deemo/src/constants.ts`. Saved sessions store **persona** indices (converted in `fromLive`), so results read `PANEL[who]` directly; older sessions had seat = persona. The ask_question `panelist` value stays the persona id (Chair/Technical/Methodology) even when Santos is "Clinical". The server reads the course at every token mint (ponytail note in `live-token.ts`).

- **Course profile:** the course comes from the account on the server (`courseOf(account.course)` in `live-token.ts` and scoring), never from the app; a null or unknown course reads as "Other". `"General"` is the domain for non-computing courses, and `fieldFocus` ignores an IT field unless the course is BSIT/BSCS. Prompts must stay program-neutral: don't re-add "BSIT" to the panel, analysis or scoring prompts (the study population lives in the paper, not the app). Keep `COURSES` identical in `server/.../identity/domain/course.ts` and the app's `constants.ts`.

- **Sequential panel = one Live session per panelist.** The engine's `seat` picks the token (`seat` in the token request), the voice and the prompt; resumption handles belong to one seat (a handover clears it). Only seat 0 touches the daily cap (`decideStart`); seats 1–2 go through `decideSeat`, which needs seat 0's start to have its token. With one panelist nothing of this runs.

- **Live voice:** chosen only at session start and kept through resumption; a voice inside the ephemeral token is ignored, so the app sends `speechConfig` in its setup message (the token leaves it unlocked). That's why each panelist has their own session (sequential panel).

- **The panel's mouth reads `panelVoice`** (`src/live/voice-level.ts`), written only by the live engines: `GeminiEngine` from an `AnalyserNode` between its voice queue and the speaker (keep it in the graph if the audio path changes), `MockEngine` with fake syllables. Tests that import an engine must mock `./voice-level` (Reanimated isn't available under `bun test`).

- **One question per panel turn is enforced on the device** (`asked`, `spokeQuestion`, `quiet` in `GeminiEngine`, all reset in `endStudentTurn`). Never word a tool refusal as something the model could say aloud or act on ("say it now"); mute instead. Any new path that hands the floor back to the student without `endStudentTurn` must reset it, or the panel's next question is refused.

- **The admin never shows transcripts, answers or manuscript analyses** (students' unpublished work, RA 10173): the session sheet is the report summary only, Manuscripts is status only. Keep it that way unless every view is audited and the consent text says admins can see them.
- **Web admin audit rows have no foreign keys** (`admin_actions`): they outlive a deleted student, and the target's email is copied in. Write every new admin action through `record()` in `server/src/modules/admin/application/actions.ts`.
- **Web admin auth:** `/admin/*` uses `authenticate` + `requireAdmin` only, never `syncUser`, so an admin's Google account never becomes a `users` row. The `admin` custom claim reaches the token only after the admin signs out and back in. Browsers can call `/admin` only from `ADMIN_ORIGINS` (plus `http://localhost:3001`).
- **Admin Firebase init is lazy** (`client/web/admin/lib/firebase.ts` `getAuth()`): Next prerenders pages at build time without the API key, so never call Firebase at module load.

- **Screen data is cached for 60 s:** focus refreshes skip the server if the list loaded under a minute ago (`freshFor` in `src/utils/fresh.ts`). After a server-side change the app makes itself, call `refresh(true)` or `invalidate` the store's freshness, or the change shows up only after a minute or a pull to refresh.

- **Presentation deck:** the phone's screens bake fonts into canvas textures, so `screens.js` waits on `document.fonts.load` first; fonts come from Google Fonts, so offline the screens and slides fall back to system fonts (libraries are vendored, fonts are not). The WebGL loop and GSAP both run on rAF: in a hidden browser tab or the hidden Claude preview pane nothing animates and freshly loaded slides look blank until a frame runs (screenshots force one). To update three.js, rebuild `vendor/three.js` from an entry that does `export * from 'three'` plus the `RoomEnvironment` addon. Slot sizes in `styles.css` decide the phone's size and position; poses live in `POSES` in `js/phone.js`. Deemo's lines and moods are the `data-say`/`data-deemo` attributes on each slide; if the app's Deemo drawing changes, port it to `js/deemo.js` too.
- **Redrawing the diagrams:** run the scripts in `docs/diagrams/src` with Node (`bun install` there first); ELK's bundled worker fails under Bun. `shot.sh` renders the HTML to a 2x PNG with headless Chrome, which only writes the file when its output goes to a pipe. Flowcharts use a hand grid on purpose: ELK reverses loops and breaks the spine.
- **Avatars:** the face is a DiceBear seed in `users/{uid}.avatar` (absent = the uid-hash default, computed by the server only). The picker shows fixed pages of faces (`pageOfFaces` in `utils/avatar.ts`: FNV-1a of `deal-<page>-<i>`, the same for everyone), so reopening it or going back to a seen page is served from the image cache; only a never-seen page downloads its 8 PNGs (under DiceBear's 10 PNG/s limit; a 429 just shows initials for that tile). Each opening starts at page 0.
- **DiceBear:** the public API is free for non-commercial use (fine for the capstone; self-host or switch to `@dicebear/core` 10.x + `@dicebear/styles` with `SvgXml` for a commercial release). It rejects a color list whose comma is URL-encoded (`%2C`), and its CDN caches by the normalized URL, so one bad request can make the good form fail too; `avatarUrl` builds the query by hand. Each avatar load tells DiceBear the device IP and the hashed seed.
- **Display names:** the server owns the name: `PATCH /me { name }` writes the `users` row, then the Firebase `displayName` (and reverts the row if Firebase refuses). The Firebase-to-row sync only fills an empty name, so a token minted before a rename can't undo it. During sign-up (email not yet verified, the server refuses) the app sets the Firebase name directly and the server copies it on the first verified request.
- **Email verification:** the server rejects unverified email accounts (403), so `use-session.ts` only loads `/me` once `user.emailVerified` is true, and the root layout only refreshes projects for `signedIn && verified`. Firebase reports verification only after `reload(user)`, and the ID token keeps `email_verified: false` until a forced refresh (`checkVerified` does both). Accounts made before this change must verify once.
- **Build and update environments are separate:** preview OTA publishes must use `--environment preview`. A correct EAS Build log and `--clear-cache` do not repair an already downloaded OTA bundle. The installed release can run the newest compatible downloaded update even offline; clearing Android app data deletes that update cache as well as the sign-in state. Repair by publishing a correct compatible update and cold-launching online; preserve app data. Keep the API URL plain text or sensitive in EAS so Update can read it. Release exports now require HTTPS; local development still permits the USB localhost fallback.
- **`EXPO_PUBLIC_*` and the Metro cache:** values are inlined into JS, and `metro.config.js` includes them in the transform cache key. The earlier cache explanation did not resolve this incident: inspection confirmed that the served preview OTA asset itself had localhost. Check the installed update and its publishing environment before rebuilding again; EAS Build's `--clear-cache` does not clear the phone's downloaded updates.
- **Started offline:** an expired Firebase ID token can't refresh without a network, and the first refresh after reconnecting may still fail; `api()` forces one refresh before giving up.
- **Session admission:** quota counts issued starts, including abandoned/early-ended rounds. The `users` row keeps `sessionDay/sessionCount` and `live_starts` keeps each start (setup fingerprint, pending lease and cached ephemeral token); on `dev` these are Firestore documents. Pending mints lease for 30 seconds; provider fetch times out after 20 seconds and failures refund only their own reservation. Token expiry stays fixed at admission (chosen length + 30 minutes); a very long pause requires a new round. Resumption reuses the same `uses: 1` token, per Google's [ephemeral-token guide](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens). These records are server-only and deleted by existing account deletion; they hold no audio/raw files. The cap applies to Live starts, not manuscript/rubric reading or report rescoring.
